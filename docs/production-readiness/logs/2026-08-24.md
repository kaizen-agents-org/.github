   proven by a real canary.

   authenticated canary, then rerun all four metric commands.

   Evidence: the only committed real artifact is issue #157 / PR #164 from
   2026-07-04; `docs/13-sandbox-smoke.md` still says no weekly smoke job is
   enabled, and `.github` #120 still tracks the first non-Node run.

   unattended Issue-to-PR completion or stack independence.

   Needed next step: enable a controlled recurring smoke, preserve a fresh
   same-stack artifact, then complete the first non-Node run.

3. The pinned onboarding/install path remains unreleased.

   Evidence: `.github` #211, #214, and #215 remain open; no implementation PR
   currently owns these installer failures.

   Impact: green core repositories do not prove that an adopter can install a
   reproducible tagged toolchain.

   Needed next step: finish the existing installer backlog and validate the
   pinned set end to end.

4. The deployed weekly metrics publication contract still conflicts with source.

   Evidence: `origin/main` docs and managed prompt require
   `docs/metrics/2026-W35.md`; this invocation initially permitted only the
   dated report and index, so PR review had to add the snapshot manually.

   Impact: the review cannot satisfy the denominator-bearing persistence
   contract without violating its runtime write boundary.

   Needed next step: deploy the source-managed three-path prompt consistently
   before the next run.

5. Verifier evaluation improved, but accepted and real-run fidelity debt remains.

   Evidence: current-main core and semantic evals pass with agreement 1 and
   false-positive rate 0; fixture eval has 3 accepted gaps. Verifier #224 and
   #226 still own contradictory builder-report blocking and scratch-artifact
   pollution; #215 owns eval-debt link maintenance.

   Impact: strong hermetic gates do not yet remove known real-run false-block
   and worktree-pollution risks.

   Needed next step: resolve #224/#226 and retire the accepted gaps with
   executable regression cases.

6. Passive PR guardian completion is incompatible with the active workflow.

   Evidence: `kaizen guardian capabilities --json` is unknown in both the
   installed and current-main CLI, while the active guardian skill requires a
   schema-v1 terminal event and durable completion notification.

   Impact: Codex can inspect immediately actionable PR state but cannot safely
   own passive CI/review stabilization without polling.

   Needed next step: align the shared guardian contract and Kaizen CLI
   capability surface, then prove one validated terminal event.

## Findings

1. Scheduled GitHub CLI authentication blocks current fleet metrics and remains unmerged.

   Evidence: all four current `kaizen status --metrics` commands failed on
   `gh issue list` with `401 Unauthorized`. `kaizen-loop` #389 and clean,
   checks-passing PR #390 own the brokered scheduled-read repair.

   Impact: the automation cannot produce denominator-bearing current outcome
   metrics, and the same credential boundary can block scheduled issue reads.

   Needed next step: complete review and merge of #390, refresh the installed
   broker/runtime, then rerun all four metrics commands.

2. The pinned onboarding/install path is still not release-ready.

   Evidence: `.github` #211 remains open for advancing the pinned onboarding
   set, while #214 and #215 track unstable global npm prefix and Volta-link
   behavior. `.github` has no open repair PR.

   Impact: a green core fleet does not guarantee that a tagged adopter install
   produces a usable, reproducible toolchain.

   Needed next step: resolve the existing install issues and validate the
   pinned set end to end before another release-readiness claim.

3. Real E2E evidence is stale and still Node-only.

   Evidence: the only committed real artifact is issue #157 / PR #164 from
   2026-07-04. Current `kaizen-loop` docs state that no weekly smoke job is
   enabled, and `.github` #120 still tracks the first non-Node dogfood run.

   Impact: package tests and hermetic evals do not prove current unattended
   operation or cross-stack completion.

   Needed next step: enable a controlled recurring smoke, record a fresh
   same-stack pass, then complete and preserve the non-Node run.

4. The deployed weekly metrics publication contract required review-time correction.

   Evidence: `origin/main` readiness docs and source-managed prompt require
   `docs/metrics/<ISO-week>.md`; this deployed prompt permitted only the dated
   report and index. Review follow-up added `docs/metrics/2026-W34.md` with
   unavailable values, inspected denominators, and failure reasons.

   Impact: without the review correction, weekly reports would not satisfy
   their own persistence contract and trend gaps would not remain durable.

   Needed next step: deploy the source-managed three-path prompt consistently,
   then rerun authenticated collection for denominator-bearing snapshots.

5. Verifier eval is healthy, but two current real-run fidelity defects remain open.

   Evidence: eval passed with no unexpected failures, while verifier #224
   tracks blocking from builder self-report despite successful executed
   commands and #226 tracks scratch artifacts entering work branches.

   Impact: real runs can still produce false blocking or polluted implementation
   commits despite strong hermetic corpus results.

   Needed next step: resolve #224 and #226, then add their final evidence to the
   regression corpus.
